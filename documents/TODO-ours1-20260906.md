# ILVR Step-wise Context Preference + Entropy: 3-Forward 최소 수정

현재 repository에는 ILVR Stage 1/2와 이전 명세에 따른 Step-wise DPO/entropy/V-off/T-off 관련 구현이 일부 또는 전부 존재한다고 가정한다.

이번 작업의 목적은 **기존 구현을 최대한 보존하면서 잘못 추가된 negative generation/reference DPO 경로만 제거하고**, 모든 reasoning step의 local V/T perturbation을 **Stage 2B training microbatch당 최대 3회의 실제 policy model forward**로 계산하도록 수정하는 것이다.

처음부터 다시 구현하지 마라.

---

## 1. Hard constraints

다음 조건을 반드시 지켜라.

```text
Stage 2B policy forward <= 3
reference forward       = 0
negative generation     = 0
autoregressive rollout  = 0
random step sampling    = 0
```

Reasoning step 수가

```text
K = 1, 4, 8, 16
```

으로 증가해도 Stage 2B의 policy forward 횟수는 최대 3으로 유지되어야 한다.

여기서 `forward`는 training microbatch에서 호출되는 실제 policy model forward invocation을 의미한다.

Gradient checkpointing의 backward recomputation은 이 counter에 포함하지 않되 별도 계측한다.

3회를 초과해야만 동작하는 구현이라면 우회하지 말고 blocker로 보고하라.

---

# 2. Reasoning semantics

각 interleaved reasoning transition은

$$
T_{k-1}
\rightarrow
V_k=(I_k^{\mathrm{helper}},Z_k)
\rightarrow
T_k
$$

로 정의한다.

* $T_{k-1}$: 직전 text reasoning block
* $I_k^{\mathrm{helper}}$: visual reasoning source
* $Z_k$: ILVR latent visual representation
* $T_k$: 현재 preference/entropy scoring target
* $P_{k-1}$: 그 이전의 clean history

모든 비교는 **clean teacher-forced trajectory**를 기준으로 한다.

$$
C_k^+
=
(Q,I_0,P_{k-1},T_{k-1},Z_k)
$$

$$
C_k^{-V}
=
(Q,I_0,P_{k-1},T_{k-1},\operatorname{Ablate}(Z_k))
$$

$$
C_k^{-T}
=
(Q,I_0,P_{k-1},\operatorname{Ablate}(T_{k-1}),Z_k)
$$

중요한 의미는 다음과 같다.

```text
clean history는 항상 유지
현재 T-V-T transition에서만 perturbation
sidecar 결과는 다음 clean step으로 propagate하지 않음
total modality removal이 아니라 local marginal intervention
```

---

# 3. 기존 구현에서 제거할 것

다음 경로는 새로운 default Stage 2B path에서 완전히 제거한다.

```text
V-off/T-off rejected text generation
T_{k,V}^- / T_{k,T}^- generation
offline negative cache
negative cache loader
reference model
reference model forward
reference log-prob cache
chosen-vs-rejected response DPO branch
online/offline autoregressive preference rollout
```

기존 파일 자체를 삭제할 필요는 없다.

다른 experiment가 사용할 가능성이 있으면 남겨두되, 새 Stage 2B trainer에서는 호출되지 않게 한다.

# 4. 정확히 세 종류의 prediction만 사용

각 $T_k$에 대해 동일한 clean target을 세 context에서 teacher forcing한다.

$$
s_k^+
=
s_\theta(T_k\mid C_k^+)
$$

$$
s_k^{-V}
=
s_\theta(T_k\mid C_k^{-V})
$$

$$
s_k^{-T}
=
s_\theta(T_k\mid C_k^{-T})
$$

여기서

$$
s_\theta(T_k\mid C)
=
\frac{1}{n_k}
\sum_{j=1}^{n_k}
\log
\pi_\theta
(t_{k,j}\mid C,t_{k,<j})
$$

이다.

별도 rejected response는 존재하지 않는다.

---

# 5. Context preference loss

각 step의 local modality dependency를 다음과 같이 정의한다.

$$
\Delta_k^V
=
s_k^+-s_k^{-V}
$$

$$
\Delta_k^T
=
s_k^+-s_k^{-T}
$$

Preference loss:

$$
\mathcal L_{\mathrm{pref},k}^{V}
=
-\log\sigma
\left[
\beta
(\Delta_k^V-\gamma_P)
\right]
$$

$$
\mathcal L_{\mathrm{pref},k}^{T}
=
-\log\sigma
\left[
\beta
(\Delta_k^T-\gamma_P)
\right]
$$

모든 step의 loss는 **각각 sigmoid를 적용한 뒤 평균**한다.

다음처럼 먼저 margin을 합쳐 하나의 sigmoid에 넣지 마라.

$$
-\log\sigma\left(\sum_k\Delta_k\right)
$$

코드 이름은 standard DPO와 혼동되지 않게 다음과 같이 사용한다.

```python
context_preference_loss(...)
```

기존 `dpo_loss.py`를 재사용할 수 있으면 파일 구조를 바꾸지 말고 해당 함수만 추가한다.

---

# 6. Entropy loss

Preference에 사용한 것과 **동일한 세 forward의 logits**를 그대로 재사용한다.

$$
p_{k,j}^{+}
=
\pi_\theta
(\cdot\mid C_k^+,t_{k,<j})
$$

$$
p_{k,j}^{-V}
=
\pi_\theta
(\cdot\mid C_k^{-V},t_{k,<j})
$$

$$
p_{k,j}^{-T}
=
\pi_\theta
(\cdot\mid C_k^{-T},t_{k,<j})
$$

$$
H(p)
=
-\sum_v p(v)\log p(v)
$$

Clean-relative entropy margin:

$$
\mathcal L_{H,k}^{m}
=
\frac{1}{n_k}
\sum_{j=1}^{n_k}
\left[
\gamma_H
-
\left(
H(p_{k,j}^{-m})
-
H(p_{k,j}^{+})
\right)
\right]_+
$$

where

$$
m\in\{V,T\}.
$$

Clean/V-off/T-off 모두 동일한 ground-truth prefix

$$
t_{k,<j}
$$

를 teacher-force한다.

이것은 leakage가 아니라 의도된 conditional comparison이다.

Entropy를 임의로 첫 token 몇 개에만 제한하지 마라.

---

# 7. 최종 loss

$$
\boxed{
\mathcal L
=
\mathcal L_{\mathrm{CE}}^{clean}
+
\lambda_P
\mathcal L_{\mathrm{ContextPref}}
+
\lambda_H
\mathcal L_{\mathrm{Entropy}}
}
$$

세 forward 결과의 사용처:

| Forward | CE | Preference |    Entropy |
| ------- | -: | ---------: | ---------: |
| Clean   |  ✓ |    $s_k^+$ |    $H_k^+$ |
| V-off   |  × | $s_k^{-V}$ | $H_k^{-V}$ |
| T-off   |  × | $s_k^{-T}$ | $H_k^{-T}$ |

추가 score/rollout용 model forward를 만들지 마라.

# 8. Stage 2B의 정확한 3-forward 구조

## Forward 1 — Clean

전체 clean teacher-forced ILVR trajectory를 한 번 계산한다.

한 번의 clean forward에서 가능한 모든 $k$에 대해 다음을 추출한다.

```text
clean CE
clean T_k token logits
clean T_k block log-prob
clean T_k entropy
sidecar에서 공유할 clean prefix representation/KV
```

---

## Forward 2 — All V-off

모든 reasoning step의 V-off branch를 **하나의 packed/batched model forward**에서 계산한다.

Step $k$의 branch는 clean prefix를 그대로 사용하고 현재 $Z_k$의 접근만 perturb한다.

```text
clean prefix up to step k
        ↓
local Z_k masking/perturbation
        ↓
teacher-forced T_k
```

Step $k$의 V-off hidden state를 step $k+1$의 prefix로 사용하지 않는다.

모든 $Z_k$를 동시에 손상시킨 하나의 global V-off trajectory를 만들지 않는다.

---

## Forward 3 — All T-off

Forward 2와 동일하게 모든 reasoning step을 한 번에 처리하되,

$$
T_{k-1}
$$

에 대한 현재 step의 access만 perturb한다.

```text
clean prefix up to step k
        ↓
local T_{k-1} masking/perturbation
        ↓
teacher-forced T_k
```

---

# 9. Causal LM label shift를 정확히 처리

`target_text_span` 자체를 그대로 attention query span이라고 가정하지 마라.

$T_k$의 첫 token $t_{k,1}$은 causal LM에서 그 직전 predictor position의 logit으로 예측된다.

따라서 각 $T_k$의 실제 prediction positions를 명시적으로 계산한다.

개념적으로 target span이

$$
[s,e)
$$

이면 predictor positions는

$$
[s-1,e-1)
$$

이다.

단, ILVR의 `<latent_end>` 및 control token 구조 때문에 실제 boundary predictor 위치는 repository의 label construction을 확인해서 결정한다.

필수 조건:

```text
T_k의 첫 token부터 V/T-off 효과가 적용되어야 함
```

이를 위해 필요하다면 sidecar에 boundary predictor position을 포함하여 재계산하되 **추가 model forward를 만들지 마라.**

---

# 10. Clean-prefix reuse

이미 구현된 cache/tree/packing infrastructure를 최대한 재사용한다.

다음 조건을 만족해야 한다.

```text
1. branch마다 full clean prefix를 재-forward하지 않음
2. clean prefix는 모든 local branch가 공유
3. 각 sidecar는 clean ancestor + 자기 branch 내부 과거만 attend
4. 다른 sidecar를 attend하지 않음
5. clean future를 attend하지 않음
6. sidecar 결과가 clean trajectory를 변경하지 않음
7. logical position / Qwen multimodal position semantics 보존
```

Cache 사용으로 별도의 네 번째 model forward를 추가해서는 안 된다.

기존 gradient semantics를 유지할 수 있도록 differentiable shared state 또는 기존 tree-packed autograd graph를 활용한다.

단순 `detach()`로 기존 학습 gradient를 변경하지 마라.

# 12. Forward-count test

실제 policy model forward entrypoint에 counter를 설치한다.

Stage 2B training microbatch마다:

```python
assert policy_forward_count <= 3
assert reference_forward_count == 0
assert negative_generation_call_count == 0
```

다음 $K$ 값에서 모두 검사한다.

```text
K=1
K=4
K=8
K=16
```

모든 경우:

$$
N_{\mathrm{policy\ forward}}\le3
$$

이어야 한다.

Sidecar가 많다는 이유로 V-off/T-off를 여러 model forward로 chunk하지 마라.

Memory가 부족하면 batch size/sequence configuration을 낮추고 3-forward constraint는 유지한다.

# 13. Correctness tests

반드시 다음 테스트를 작성한다.

### A. Local perturbation

$T_k$ V-off가 오직 현재 $Z_k$ access에만 영향을 주는지 확인한다.

### B. Clean prefix identity

모든 sidecar의 $P_{k-1}$이 clean branch와 동일함을 확인한다.

### C. No propagation

$k$번째 sidecar 결과가 clean $T_{k+1}$에 들어가지 않음을 확인한다.

### D. Teacher-forcing identity

Clean/V-off/T-off가 동일한 target $T_k$와 동일한 $t_{k,<j}$를 사용함을 확인한다.

### E. First-token correctness

$T_k$의 첫 token prediction부터 V/T perturbation이 적용되는지 확인한다.

### F. Loss reuse

CE/preference/entropy가 정확히 clean/V-off/T-off 세 logits만 사용함을 확인한다.

### G. No legacy compute

Stage 2B 실행 시 다음이 호출되지 않음을 검사한다.

```text
negative generation
reference policy
rejected-response branch
```

### H. Baseline regression

`step_preference.enabled=false`이면 기존 ILVR Stage 2 동작이 보존되어야 한다.
