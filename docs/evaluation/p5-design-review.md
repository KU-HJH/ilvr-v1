## macrothink 적용 여부

이번에는 생략한다. 사용자가 mini, 규칙 기반 접근, 구체적 지원 범위를 차례로 선택했고 실제 데이터 400개도 검사했다. 현재 gate에는 모집단·목적·대규모 실행 경로의 선택이 남아 있지 않다. 다른 문제를 푸는 비용보다 bounded fresh-read를 추가할 이득이 크다는 근거가 없다. 이는 방향이 옳다는 증거가 아니며, 새 모델의 unsupported 진단이 많아지는 경우 방향을 재검토해야 한다.

## prism

서로 다른 두 실패 경로를 root가 분리해서 읽었다. 독립 agent 또는 모델 다양성 검증으로 표현하지 않는다.

- **평가 적용 가능성 — unclear:** 공개 Qwen 한 파일의 구문 분포로 다른 모델에서 의미상 정답 누락이 점수 비교에 미치는 영향을 판정할 수 없다.
- **입력 실행·자원 경계 — pass, 설계 명세에 한정:** 임의 문자열 실행을 금지하고 생성자/전개 전에 확인하는 유한 문법과 연산 제한을 명시했다. 구현이 이를 실제 지키는지는 아직 검증되지 않았다.

한쪽의 pass를 전체 pass로 평균하지 않는다. 판단을 가르는 질문은 **이 명시적 수정 profile을 CPU 계약과 실제 입력 보존까지 구현하되, 적용 모델의 응답 형식에 따른 의미상 정답 누락과 원본/논문 점수 동등성은 미검증으로 남기는 범위를 승인할지**다. 최종 commitment에서 이 제한을 그대로 제시한다.

## mandela

검증 구성: 앞으로 구현할 scorer, root가 설계하는 CPU fixture, 독립된 고정 HF 데이터의 정답, 공개 Qwen 응답이다. 신규 ILVR 모델 추론은 없다.

발화하는 패턴은 **Shared hallucination / Tautology**다. 자체 parser와 자체 fixture가 맞는다는 결과를 benchmark 의미 정확성으로 확대하면 설계자가 정한 지원 범위를 다시 채점하는 순환이 된다. 독립성 조치는 원본 데이터 정답·이미지를 별도로 고정하고, target 없이 추출하며, 데이터 대응·원본 함수 관찰·수정 규칙 CPU 계약을 따로 보고하는 것이다. 공개 결과의 true_false를 정답 oracle로 사용하지 않는다. 자체 fixture pass와 이 hook 판정은 위 first_nail의 독립적인 의미 대조를 대신하지 않는다.

## Superpowers 합성 결정

제안 v1의 문제·scope·interface·동작을 바꾸는 비평 수정은 없다. 평가 적용 가능성의 unclear를 유지하고, first_nail not_run 및 원본 환경/GPU/전체 모델 평가/논문 프로토콜 미검증을 최종 commitment에 포함한다. 보안 lens는 실행 pass가 아니라 명세 수준 판정이다. 인간의 최종 written-spec 승인은 아직 받지 않았다.

Root는 이를 독자 오류로 돌리지 않고 v2에서 각각 **필터 없음/허용 목록 검사**와 **연속 거듭제곱 거부**로 명확히 했다. 후속 first-nail의 실제 응답 corpus와 재검토 조건도 구체화하라는 제안은 첫 실제 고정 manifest prediction run, 의미상 정답 누락 1개 이상 발견 시 cross-model 비교 전 정책 검토로 반영했다. 아직 그 run은 없고 생성도 승인되지 않았다.

## 최종 v2 승인과 계획 독해

2026-09-13 사용자가 v2 최종 문서와 한계를 승인했다. 그 뒤 작성한 실행 계획 499줄과 승인 spec 108줄의 독립 사본을 context-free agent `p5_plan_cold_read`가 전부 읽었다. 판정은 **needs work**였다. 이는 앞의 v1 spec 독해를 반복한 것이 아니라 새 실행 handoff 자료의 독해다.

중요 발견: 계획이 분자/분모 각각에 1e100을 적용해 `(1e-100)^2`를 거부하는 것은 spec의 실수 값 제한과 다르다. Root는 이 발견을 수용하고 “운영상 해석”이라는 설명과 해당 제한을 철회했다. 부수 발견인 empty selected candidate 진단 이름과 집계 포함 여부, spec 첫머리의 오래된 승인 대기 문구도 수정한다. 해당 독자가 수정 후 plan/spec까지 재검증했다고 주장하지 않는다.

## design proposal v3 — 새 안전 한도에 대한 비평

대상은 [v3](p5-design-proposal-v3.md), SHA-256 `e7640811ef1c5f55f6621a0bea3d0c7a8d79942a037083a24a2785bd3b54b28e`다. 기존 v1/v2는 보존한다. 이 pass의 변경 대상은 별도 4,096비트 분자/분모 한도이며 세부 진단 이름도 고정했다. 동일한 동결 v3를 hate와 prism이 읽었고 사이에 수정하지 않았다.

**hate:** {root: "큰 수를 이미 생성한 뒤 4,096비트 한도를 검사하면, 명시한 한도가 있어도 원래의 계산량 폭증 위험을 막지 못한다.", first_nail: "Task 1에서 작은 수의 정상 거듭제곱과 한도 초과 중첩 거듭제곱을 대조하고, 초과 입력에 대해 큰 SymPy power/rational 생성 전 차단되는지 호출 관찰로 검사한다. 최종 값만 진단하는 테스트로 대체하지 않는다."}

상태 **not_run**. 새 parser가 없고 설계 승인 전 구현성 prototype은 만들지 않는다. 순수 정수 크기 계산에서 1e200의 분모는 665비트, 1e6400의 분모는 21,261비트임만 확인했다. 이는 입력 예시의 크기를 검산한 것으로 실제 생성 차단의 증거가 아니다. 구현 Task 1의 초기 CPU 안전 계약에 이 관찰을 포함한다.

**prism:** 입력 실행/자원 경계는 **unclear**(실제 생성 전 검사 순서는 구현으로 확인해야 함), 평가 적용 가능성도 **unclear**(v3의 추가 한도를 포함한 표현 지원 범위가 모델별 점수에 미치는 영향은 아직 모름)다. 서로 다른 이유로 미검증이라는 데 일치한다. 단일 승인 질문은 **명시한 4,096비트 수정 경계와 생성 전 차단의 미검증 상태를 받아들이고, 그 차단을 우선 검증하는 오프라인 구현 계획까지 진행할지**다. 같은 모델의 동의로 안전성을 증명하지 않는다.

macrothink는 모집단·목적을 새로 선택하지 않으므로 계속 생략한다. mandela 조치는 그대로다: 독립 dataset 정답을 유지하고 추출에 gold를 주지 않으며 자체 CPU 계약을 모델 성능 인증으로 확대하지 않는다. 이전 실제-model first-nail도 not_run으로 남긴다. v3의 보안 한도는 기존 v2 승인에 포함됐다고 간주하지 않고 최종 설계와 계획을 함께 인간 검토에 제시한다.
